## Summary
Add a public `chunk(input, size)` helper that splits a string into consecutive pieces measured in Unicode code points.

## Current behaviour
`src/textkit.js` has no exported `chunk` helper. `wordWrap` does split overlong words into code-point-sized pieces internally, but does not expose those pieces as an array.

## Desired behaviour
`chunk(input, size)` returns an array of consecutive chunks, each containing at most `size` code points. The final chunk may be shorter. Empty input returns `[]`. Throw `RangeError` unless `size` is a positive integer.

## Key interfaces to change
- `src/textkit.js`: add the named export `chunk(input, size)` with a JSDoc block and `@example`.
- `test/textkit.test.js`: import `chunk` and cover its normal and edge cases.
- `README.md`: add `chunk` to the import example and document it in the API section.

## Acceptance criteria
- [ ] `chunk('abcdefg', 3)` returns `['abc', 'def', 'g']`.
- [ ] `chunk('', 2)` returns `[]`; exact-size chunks and a shorter final chunk work.
- [ ] Chunk boundaries count Unicode code points, e.g. `chunk('😀😀😀', 2)` returns `['😀😀', '😀']`.
- [ ] Zero, negative, fractional, or otherwise non-positive-integer sizes throw `RangeError`.
- [ ] Tests cover normal use, empty input, unusual Unicode input, and invalid sizes.
- [ ] JSDoc and README API documentation include an example; `npm test` passes.

## Out of scope
Changing `wordWrap` behaviour or requiring its inline splitting to be refactored; grapheme-cluster segmentation; validation of non-string `input` values; unrelated helpers or dependencies.
