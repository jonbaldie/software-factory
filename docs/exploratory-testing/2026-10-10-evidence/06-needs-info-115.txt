## Summary
Fix `slugify` so German sharp S is transliterated to `ss` instead of being treated as a separator.

## Current behaviour
`slugify` in `src/textkit.js` applies NFKD normalization, removes combining marks, lowercases, replaces runs outside ASCII letters and digits with `-`, then trims boundary hyphens. Since `ß` survives normalization, `Straße` becomes `stra-e` and `Großer Preis` becomes `gro-er-preis`.

## Desired behaviour
Expand `ß` to `ss` before ASCII slug filtering, preserving the rest of the existing slug rules. The reported titles should produce `strasse` and `grosser-preis` respectively.

## Key interfaces
- `slugify(input)` in `src/textkit.js`; no signature change.
- Regression tests in `test/textkit.test.js`.
- Keep the existing API entry in `README.md` accurate if its description needs updating.

## Acceptance criteria
- [ ] `slugify('Straße')` returns `strasse`.
- [ ] `slugify('Großer Preis')` returns `grosser-preis`.
- [ ] Sharp-S handling is covered by tests; uppercase `ẞ` should also work if lowercasing it in the chosen implementation.
- [ ] Existing accent, punctuation, boundary-hyphen, and empty-input behavior remains unchanged.
- [ ] `npm test` passes.

## Out of scope
- Broader German transliteration (for example, changing `ö` to `oe`), transliteration of other scripts or symbols, or changes to the general slug policy.

## PR #116
slugify makes broken slugs for some page titles
head: 6f84943f2849577e2bacdb3352fd4a214de0d270
labels: agent:approved

Updated `slugify` to convert German sharp S to `ss` before ASCII filtering. Added regression coverage for `Straße`, `Großer Preis`, and uppercase `ẞ`, and updated the JSDoc and README API entry. `npm test` passes all 130 tests.

**Root cause:** NFKD normalization leaves `ß` unchanged, so the ASCII-only filter treated it as a separator. A probe adding only `ß`-to-`ss` expansion before filtering produced the expected slugs. Before the fix, the regression test failed with actual `stra-e` versus expected `strasse`.

**Decisions:**
- Kept the change narrowly scoped to sharp S, preserving the existing slug rules.
- Applied the expansion after lowercasing so uppercase `ẞ` is handled too; broader transliteration remains out of scope.

Closes #115
