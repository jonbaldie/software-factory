## Install and update the factory

The goal was to install the factory, preserve an explicit setup choice on reinstall, and recover from a symlinked destination without damaging existing data. The [replay script](2026-10-31-evidence/installer-journey.py) ran `install.sh` in a fresh fixture. The [output](2026-11-07-evidence/installer.log) records each command and saved variable state.

1. A fresh install returned exit 0, detected `npm test` and `npm ci`, and copied the scout workflow byte for byte from the source template.
2. An install with `--setup-command ''` and a subsequent ordinary reinstall both returned exit 0. The simulated GitHub state retained `FACTORY_SETUP_DISABLED=true` and no setup command. Re-enabling `npm ci` and reinstalling retained `FACTORY_SETUP_COMMAND=npm ci` and removed the disabled marker.
3. Replacing the installed review prompt with a symlink made the installer exit 1. The shared file, another installed prompt, and the saved variables remained unchanged. After removing the symlink, a retry returned exit 0 and restored the review prompt from the template.

The refusal message named the symlink and the required retry. After setup was disabled, the installer displayed `FACTORY_SETUP_COMMAND (none)` without stating that the choice would persist. The saved disabled marker was visible in the simulated state, but not in that output. The simulated GitHub CLI cannot establish actual permissions, network behavior, or persistence on GitHub. The replay did not add a model key, commit the installed files, or start an agent.

The commands `python3 tests/install.py` and `python3 tests/pi.py` exited successfully. Python was used directly because `uv` was unavailable. Their [installer](2026-11-07-evidence/installer-suite.log) and [pi parser](2026-11-07-evidence/pi-suite.log) outputs use test doubles and are not live Actions checks. The original logs do not include the commands or exit codes.
